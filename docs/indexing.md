## 1. 임베딩 모델 결정

**결정: OpenAI `text-embedding-3-small` (1536차원, 코사인 유사도)** — `indexer/embed.py`

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **text-embedding-3-small** | 한국어 포함 다국어 검색 성능 검증, API라 GPU 불필요, $0.02/100만 토큰 | 외부 API 의존 | **채택** |
| text-embedding-3-large | 3072차원, 일반적으로 검색 성능 더 높음 | 6.5배 비용, 벡터 2배 용량 | 보류 — §6 실패 분석상 모델보다 검색 방식(하이브리드·시점 필터) 문제가 커서 그 뒤에 비교 |
| bge-m3 / multilingual-e5 (로컬) | 무료, 오프라인 | 이 PC는 GPU 없음 → 청크 4.7만 개 × 설정 3개를 CPU로 임베딩하면 수 시간, 모델 내려받기 2GB+ | 6일 일정에 맞지 않음 |

- **비용·시간 실측**: 청킹 설정 하나(청크 약 4.5~5.4만 개, 약 2,800만 자)를 임베딩하는 데 약 30~40분(계정 한도 분당 100만 토큰에 맞춰 속도 조절), 비용은 약 $0.4~0.5.
- **캐시**: `store/embeddings/{model}.sqlite`에 텍스트 해시 → 벡터로 저장. 같은 텍스트는 다시 요청하지 않으므로 문서를 추가하면 새 청크만 임베딩한다.
- **계층 분리**: 문서 임베딩은 인덱서(②)만 만든다. 챗봇(④)은 질의 임베딩만 같은 모델로 만든다(`rag/retriever.py`).

## 2. 청크 메타데이터 항목 (확정)

VectorDB에 청크와 함께 저장하는 항목. 모두 스칼라 값(문자열·정수)으로, Chroma 메타데이터 필터에 바로 쓸 수 있다.

| 항목 | 예시 | 용도 |
|---|---|---|
| `chunk_id` | `dart:20241022800030#0` | 청크 식별 (`{doc_id}#{순번}`) |
| `doc_id` | `dart:20241022800030` | 원문(docs.db) 조회, **평가 정답 매칭**, 문서 단위 중복 제거 |
| `chunk_index` / `n_chunks` | `0` / `2` | 인접 청크 확장, 문서 내 위치 |
| `source_type` | `news` `disclosure` `patent` `report` `policy` | **출처 종류별 근거 분리 제시**, 필터 |
| `evidence_role` | `current` `leading` `outlook` | **시간축 근거 구분** (현재·선행·전망) → 상충 비교 |
| `origin` | `provided` `dart` `kipris` `bioin` `korea_kr` | 수집 경로 |
| `title` | `[삼성바이오로직스] 의약품 위탁생산계약 …` | 답변의 출처 표시 |
| `publisher` | `삼성바이오로직스` / `머니투데이` / `KOTRA` | 출처 표시, 매체 다양성 |
| `published_at` | `2024-10-22T00:00:00` | **시점 질문**: 기간 필터·최신순 정렬 |
| `year` / `quarter` | `2024` / `2024Q4` | 기간 필터 (Chroma는 문자열 범위 비교가 약해 정수 연도를 따로 둠) |
| `url` | DART 뷰어·네이버 기사·특허 DOI·정책브리핑 링크 | 출처 링크 (수집 원칙: 모든 문서 URL 기록) |
| `section` | `II. 사업의 내용 > 1. 사업의 개요 > 가. 사업개요` / `청구항` | 청크 위치 설명, 특허 항목 구분 |
| `content_kind` | `text` / `table` | 표 청크 구분 (답변 시 표 그대로 인용) |
| `topics` | `ADC; 신약 기술수출` | 하위 주제 필터 |
| `is_outlook` | `1` | 전망 수치 포함 여부 → 뉴스↔보고서 상충 후보 |
| `event_id` | `ev:naver:…` | 같은 사건 뉴스 묶음 → 검색 결과 다양화(사건당 상한) |
| `company` | `리가켐바이오` | 기업별 필터 (공시 회사·특허 출원인) |
| `category` | `기술이전·라이선스` / `watch` / `KR` / `보건복지부` | 공시 분류·보고서 게시판·특허 국가·부처 |
| `char_len` | `772` | 길이 분포 점검 |
| `config` | `structure` | 청킹 설정 |

본문은 두 가지로 저장한다: `text`(임베딩·검색 대상, 머리말 포함)와 `body`(답변 인용용, 머리말 제외).

## 3. 파싱 · 정제 — `indexer/parse.py`

원문 추출(HTML·XML·HWPX·PDF → 텍스트)은 수집 단계에서 끝났고, 인덱서는 **문서 종류별 구조에 맞게 섹션으로 나누고 남은 보일러플레이트를 지운다.**
구조는 EDA에서 종류별 샘플을 직접 읽어 확인했다.

| 종류 | 확인한 구조 | 섹션 분할 | 제거한 것 | 지식베이스 기준 제거량 |
|---|---|---|---|---|
| 뉴스 | 줄바꿈 없는 한 덩어리(100%), 리드 문장에 핵심 | 1개 | 기자명·구독 안내(본문 끝 150자 안에서만) | 0.03% (대부분 수집 단계에서 이미 제거) |
| 공시 | `항목 \| 값` 표 줄. 사업보고서는 `II.`·`1.`·`가.`·`(1)` 헤딩 계층 | 수시공시 1개, 사업보고서 헤딩 경로별 (평균 3.2, 최대 136) | 투자 유의 상용구 | 5.9% |
| 특허 | 서지 줄(명칭·출원인·IPC) + `요약:` (+ `청구항`) | 서지·요약 / 청구항 | — | 0% |
| 보고서 | `□ ○ ■ 【】 1.` 헤딩, 39%(284건)는 PDF 변환으로 **단어마다 줄바꿈** | 헤딩 기준 | `(계속)` 꼬리, 머리 서지 줄, 단어별 줄바꿈 복원, `있다 .` 같은 공백 | 7.6% |
| 정책 | 제목·부제(`- … -`) + `□` 문단, 하단 붙임·의견 제출 안내 | `□` 기준 | 붙임·별첨 목록, 의견 제출 방법, 담당자 표 | — |

**개인정보 정제 (수집 원칙 보완)** — `collector/storage.py: scrub_personal`
- EDA 중 공시 본문에 **공시책임자·공시담당자 이름과 전화번호**가 남아 있는 것을 발견했다(191건).
- 이름이 들어가는 짧은 줄은 통째로 지우고, 연락처 줄의 번호는 `[전화번호]`로 바꾸도록 저장 단계(`save_documents`)에 넣어 앞으로 수집되는 모든 문서에 적용된다. 기존 문서 203건에도 적용했다.
- 정책 보도자료는 수집 단계에서 담당자 표를 통째로 잘라낸다.

**정제 중 발견해 고친 버그**
1. 뉴스 꼬리 제거 정규식이 본문 중간의 '공감'·'구독'에서 이후 전체를 잘라냈다(뉴스는 한 줄이라). → 마지막 150자 안에서만 적용. 이 버그로 뉴스 20건이 청크를 하나도 남기지 못했었다.
2. 개인정보 정제가 '담당자(' 등을 포함한 **한 줄짜리 본문 전체**를 지웠다(뉴스 2건, 공시 2건). → 200자 이하 줄만 지우도록 고치고, 원문 캐시(DART zip·제공 CSV)에서 복원했다.

## 5. 청킹 전략 (3개 설정) — `indexer/chunk.py`

| 설정 | 분할 | 머리말 | 의도 |
|---|---|---|---|
| `fixed` | 모든 문서 동일: 800자 창, 100자 겹침, 창 끝 20% 안 문장 경계에서 자름 | 제목·출처·날짜 | 기준선 |
| `structure` | 문서 종류별 (아래 표) | 제목·출처·날짜·섹션 | 문서 구조 반영 |
| `structure_notitle` | `structure`와 동일 | **없음** | 청크에 제목을 넣는 효과 측정 |

`structure` 설정의 종류별 규칙 (근거는 §3의 구조 확인)

| 종류 | 단위 | 목표 길이 | 겹침 | 근거 |
|---|---|---|---|---|
| 뉴스 | 문장 | 600자 | 1문장 | 중앙값 1,466자 → 2~3청크, 리드에 핵심. 중복 처리 후 분할 |
| 정책 | 문장(`□` 문단) | 500자 | 1문장 | 구조적이고 핵심이 앞부분 → 짧게 + 겹침 |
| 보고서 | 헤딩 섹션 내 문장 | 900자 | 1문장 | 헤딩이 의미 단위, 표는 행 단위로 따로 |
| 공시 | 표 행 | 1,000자 | 없음 | 수시공시는 대부분 1청크, 표 행을 자르지 않음. 사업보고서는 헤딩 섹션별 |
| 특허 | 항목 | 서지·요약 1청크, 청구항 1,000자 | 없음 | 항목 구조 고정 |

공통: 목표 길이의 40%가 안 되면 다음 단위까지 붙이고(제목 줄만 있는 청크 방지), 120자 미만 꼬리는 앞 청크에 합친다. 1,200자 넘는 표 행은 문장으로 나눈다.

### 청크 길이 분포 (지식베이스 15,379건)

| 설정 | 청크 수 | 5% | 25% | 중앙값 | 75% | 95% | 150자 미만 | 1,500자 초과 |
|---|---|---|---|---|---|---|---|---|
| fixed | 45,522 | 254 | 626 | 743 | 778 | 798 | 201 (0.4%) | 0 |
| structure | 54,224 | 222 | 441 | 543 | 588 | 944 | 341 (0.6%) | 141 (0.3%) |

| 종류 | fixed 청크 (중앙값) | structure 청크 (중앙값 / 95%) |
|---|---|---|
| 뉴스 | 23,742 (743자) | 31,270 (550 / 597) |
| 공시 | 9,719 (765) | 8,022 (794 / 1,019) |
| 특허 | 4,434 (474) | 4,268 (472 / 835) |
| 보고서 | 3,749 (756) | 3,907 (774 / 1,049) |
| 정책 | 3,878 (750) | 6,757 (438 / 499) |

- 1,500자 초과 청크(141개)는 대부분 공시의 긴 표 행(전환가액 조정 조항 등)이다. 문장 경계가 없어 그대로 두었다(최대 2,000자).
- 150자 미만은 짧은 수시공시·특허 초록이 대부분으로, 문서 자체가 짧은 경우다.

## 6. 청킹 설정 비교 (평가셋 Hit@k) — `python -m eval.retrieval_eval`

임베딩 `text-embedding-3-small`, 코사인 유사도 상위 청크를 문서 단위로 중복 제거한 순위. 답변 가능 68문항(답변 불가 11문항 제외).

| 설정 | 청크 | Hit@1 | **Hit@3** | Hit@3 (엄격) | Hit@5 | Hit@10 | MRR |
|---|---|---|---|---|---|---|---|
| fixed | 45,522 | 0.368 | 0.529 | 0.500 | 0.632 | 0.691 | 0.473 |
| **structure** | 54,224 | **0.368** | **0.603** | **0.544** | **0.647** | **0.735** | **0.495** |
| structure_notitle | 54,224 | 0.235 | 0.382 | 0.368 | 0.485 | 0.618 | 0.344 |

| 유형별 Hit@3 | 사실 (36) | 비교 (9) | 시점 (14) | 종합 (9) |
|---|---|---|---|---|
| fixed | 0.639 | 0.667 | 0.429 | 0.111 |
| **structure** | **0.722** | 0.667 | **0.571** | 0.111 |
| structure_notitle | 0.500 | 0.222 | 0.286 | 0.222 |

- **엄격 기준**: 평가셋에 적은 정답 문서만 인정. **기본 기준**은 여기에 두 가지를 더 인정한다.
  - 같은 공시의 [정정]본
  - 같은 발표를 다룬 다른 기사 중 답의 수치가 본문에 있음을 직접 확인한 문서(`also_accept`, F11·F27)
- 확장은 세 설정에 똑같이 적용했고, 엄격 기준에서도 순위는 같다.

**결정: `structure` 채택**
1. Hit@3이 `fixed`보다 7.4%p(엄격 4.4%p) 높고, Hit@10·MRR도 가장 높다. 특히 시점 질문(+14%p)과 사실 질문(+8%p)에서 차이가 난다.
   - 공시 표 행을 자르지 않아 금액·날짜가 한 청크에 남는다.
   - 섹션 경로가 머리말에 들어가 문맥이 보존된다.
2. **청크에 제목을 넣는 효과가 가장 크다**: 같은 분할에서 머리말을 빼면 Hit@3이 0.603 → 0.382(−22%p)로 떨어진다.
   - 공시·특허는 본문만으로는 어느 회사의 어떤 계약인지 알 수 없다.
   - 그래서 머리말(제목·발행처·날짜·섹션)은 필수로 유지한다.
3. 청크 수는 19% 많지만(54k vs 46k) 임베딩 비용 차이는 1회 $0.1 미만이다.

**실패 문항 분석 (structure, Hit@3 실패 27건) → 검색 단계 개선 과제**

| 원인 | 문항 | 관찰 | 개선 방향 (rag/retriever) |
|---|---|---|---|
| 표 위주 공시가 뉴스에 밀림 | F13, T01, T02, F17 | 실적 전망·출자 공시는 본문이 `매출액 \| 55,705` 같은 표라 의미 유사도가 낮고, 같은 내용을 쓴 기사가 위로 옴 | 공시 분류명(`실적전망` 등)을 머리말에 추가, BM25 결합(하이브리드) |
| 시점 조건 무시 | F12, T08, T10 | "2024년 10월" 질문에 2023년 화이자 계약 기사가 1~3위 | 질문의 연도·월을 `published_at`·`year` 메타데이터 필터로 |
| 같은 회사의 비슷한 공시가 많음 | F04, F06, F08, F09, C02 | 리가켐바이오·알테오젠의 다른 계약 공시가 위로 옴 (상대방·제품 코드만 다름) | 고유명사(LCB14, SOTIO, ALT-B4) 키워드 매칭 → 하이브리드 |
| 종합 질문 | S01~S08 | 관련 문서는 찾지만 평가셋의 특정 정답 문서가 아님. 정답 문서가 여러 개라 Hit@3로는 과소평가됨 | 다중 질의(쟁점별 하위 질의)로 근거 다양화, 답변 채점은 직접 평가 |
| 사건당 기사 다양성 | C05, S02 | 같은 주제의 다른 시장 규모 기사가 위로 옴 (상충 비교에는 오히려 유용) | `event_id`·출처 다양화(MMR) |

**답변 불가 판정 참고**
- 상위 1위 유사도 중앙값이 답변 가능 0.638, 답변 불가 0.579로 분포가 겹친다.
- 그래서 유사도 임계값만으로는 거절을 판정할 수 없다. 생성 단계에서 근거 충분성을 판단하게 해야 한다.

**임베딩 모델**
- 3-large 비교는 하지 않았다. 실패 원인 대부분이 표 형식·시점 필터·고유명사 매칭이라 모델을 바꿔도 해결되지 않을 가능성이 높다.
- 하이브리드 검색을 먼저 적용하고, 그 뒤에도 부족하면 같은 평가셋으로 비교한다(설정 하나 약 $3).

- 답변 불가 유형은 세 가지를 섞었다: 지식베이스 기간 밖(2027년 등), 주제 범위 밖(화장품·의학 조언·투자 권유), **근거 문서는 있지만 질문한 수치가 비공개**(U02). 부족 자료 탐색에서 보강하지 않은 현장 반응(U10)도 넣었다.
