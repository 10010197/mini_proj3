## 1. 중복 내용 처리 (제공 뉴스) — `collector/dedup_news.py`

### 1.1 기준과 임계값

| 구분 | 판별 기준 | 임계값 | 처리 |
|---|---|---|---|
| **완전 중복** | URL(언론사ID+기사ID) 일치 / 정규화한 본문 일치 | 완전 일치 | 1건만 유지 (`load_provided.py`) |
| **재배포본** | 본문 문자 5-gram Jaccard 유사도 | ≥ 0.50 이고 발행 간격 ≤ 3일<br>또는 포함도 ≥ 0.80·유사도 ≥ 0.40<br>또는 유사도 ≥ 0.80 (기간 무관) | 클러스터 대표 1건 유지, 나머지 제외 |
| **동일 사건 유사 기사** | 발행 간격 ≤ 1일 이고 (유사도 ≥ 0.15·제목 단어 겹침 ≥ 0.30) 또는 유사도 ≥ 0.30 | — | 같은 `event_id`로 묶음 |
| └ 내용 동일 | 짧은 기사가 긴 기사에 포함도 ≥ 0.70 이고 새 수치 없음 | 0.70 | 긴 기사로 축약 |
| └ 관점 상이 | 위 조건을 만족하지 않음 | — | **유지** (지식베이스에는 사건당 최대 3건) |
| **수치 보호 (공통)** | 제외 후보가 대표에 없는 수치(금액·비율·건수)를 2개 이상 담음 | 2개 | 제외하지 않고 유지 |

- **유사도 계산**: 공백·기호를 뺀 본문 앞 3,000자(95% 분위 길이)를 문자 5-gram으로 나누고, 해시값 1/4 표본으로 Jaccard와 포함도(작은 쪽 기준 겹침 비율)를 구한다.
- **후보 쌍**: 발행 1일 이내 모든 쌍 + MinHash LSH로 찾은 기간 무관 고유사 쌍(합계 약 78.7만) → 유사도 0.15 이상이거나 제목이 겹치는 61,421쌍만 판정에 쓴다.
- **대표 선정**: 수치가 가장 많은 기사 → 본문이 긴 기사 → 먼저 보도된 기사 순. 정보가 가장 많은 판본을 남기기 위함.

### 1.2 임계값 설정 근거
탐색 단계에서 후보 쌍 68,688개(유사도 0.1 이상 또는 제목 겹침 0.3 이상)를 유사도 구간별로 나누고, 구간마다 표본 기사 쌍을 직접 읽어 정했다.

| 유사도 구간 | 쌍 수 | 표본에서 관찰된 내용 | 결정 |
|---|---|---|---|
| ≥ 0.8 | 2,869 | 같은 보도자료를 거의 그대로 전재 (제목만 다름) | 재배포본 |
| 0.6 ~ 0.8 | 7,684 | 같은 보도자료를 문장 순서·어미만 바꿔 작성 | 재배포본 |
| 0.5 ~ 0.6 | 6,348 | 같은 보도자료 기반, 리드 문장만 다름. 일부는 한쪽에만 금액이 있음 | 재배포본 (단, 수치 보호 적용) |
| 0.3 ~ 0.5 | 19,430 | 같은 발표를 다룬 기사. 한쪽이 배경·전망·업계 반응을 덧붙인 경우가 섞임 | 동일 사건 → 포함도로 판단 |
| 0.15 ~ 0.3 (제목 겹침 ≥ 0.3) | 6,946 | 같은 사건, 매체별 취재 내용이 다름 | 동일 사건 → 대부분 유지 |

- **발행 간격 조건**: 유사도 ≥ 0.5인데 7일 넘게 떨어진 쌍(95쌍)을 보면 공모주 청약 기사와 상장 기사처럼 **같은 회사의 다른 사건**이 섞여 있어, 재배포본은 3일 이내로 제한했다. 0.8 이상은 공지 재게재 등 실제 중복이라 기간을 보지 않는다.
- **수치 보호 2개 기준**: 처음에는 1개로 했지만, 삼성의 그레일 투자 기사(1.1억 달러 / 1,550억 원 / 1,560억 원)처럼 **단위 환산 차이**만으로 재배포본 10건이 남았다. 2개로 올리자 남는 재배포본이 612건 → 185건으로 줄었고, 실제로 다른 정보(계약 상대·추가 금액)를 가진 기사만 남았다.
- **관점 상이 기사를 남기는 이유**: 같은 사건이라도 "기회"로 보는 기사와 "우려"로 보는 기사가 함께 있어야 상충 정보를 제시할 수 있다. 대신 한 사건이 검색 상위를 독점하지 않도록 지식베이스에는 사건당 최대 3건만 넣고(`select_kb.EVENT_CAP`), `event_id`는 검색 단계에서도 결과 다양화에 쓴다.

## 2. 부족 자료 탐색 — `eval/kb_coverage.py`

대표 질문 17개(`eval/questions.json`)마다 검색식을 정하고, 질문이 요구하는 출처별로 지식베이스에 근거 문서가 있는지 셌다.
임베딩 전이라 키워드 검색으로 **존재 여부**만 확인했다. 기준: 뉴스 5건, 공시 3건, 특허 10건, 보고서 3건, 정책 2건 이상.

### 2.1 근거 유형 구분

| 질문 | 요구 근거 | 뉴스로 충족? | 판단 |
|---|---|---|---|
| Q01 CDMO 수주·증설 | 뉴스 + 공시 | 부분 | 수주 금액·상대는 공시(1차)로 확인 |
| Q02 비대면 진료 제도 변화 | 뉴스 + **정책 원문** + 보고서 | ✗ | 기사는 제도를 요약·해석할 뿐, 대상 환자·처방 기준은 보도자료 원문 필요 |
| Q03 디지털 헬스케어 투자 유치 | 뉴스 | ○ | 투자 유치는 기사로 충분 |

| Q05 AI 신약개발 특허 실체 | 뉴스 + 특허 | ✗ | 동일 |

| 항목 | 내용 |

**정제 (개인정보 포함)** — 보도자료는 담당 부서·직위·이름·전화번호를 반드시 포함하므로 저장 전에 지운다.

- 확인: 직위만 있는 줄이 남은 문서 0건. 이름 형태의 짧은 줄은 행사 일정표의 발표자 등만 남음
- HWPX는 표를 품은 문단과 셀 문단이 이중으로 추출되는 문제가 있어 바깥 문단을 건너뛰도록 고쳤다
