# 평가 하네스 — `eval/run_eval.py`

> 평가셋([eval/eval_set.jsonl](../eval/eval_set.jsonl), 79문항) 전체를 **챗봇과 같은 체인 `rag.chain.ask()`** 로 실행한다.
> 그다음 검색·인용·거절·답변 정확도·근거 충실도를 한 번에 측정한다.
> 평가셋 구성과 작성 원칙은 [indexing.md §7](indexing.md), 검색 단독 비교(청킹 설정별)는 [indexing.md §6](indexing.md)을 본다.

## 1. 구조

```
eval_set.jsonl ─▶ rag.chain.ask(q)  ◀── app/(챗봇)도 같은 함수를 호출
                    │  retriever.search: 벡터(Chroma) + BM25 + 질문 연도 → RRF (기본 hybrid_time, §6), 문서당 2청크 · 상위 6문서
                    │  prompts: 근거 번호 인용, 출처 종류·시간축 구분, 거절 규칙("[답변 불가]"로 시작)
                    │  ChatOpenAI (CHAT_MODEL, 기본 gpt-5.4-mini)
                    ▼
            답변 · 근거 목록 · 인용 번호 · 토큰 · 지연
                    │
                    ├─▶ 검색·인용·거절 지표 (규칙 기반)
                    ├─▶ LLM 채점 (JUDGE_MODEL, 기본 gpt-5.4): 정확도 · 근거 충실도 · 상충 처리
                    └─▶ 사람 검토용 CSV (manual_score 칸)
```

- **같은 체인 호출**: 하네스는 검색·프롬프트·생성을 따로 구현하지 않고 `rag.chain.ask()`만 부른다. 그래서 챗봇의 검색 설정이나 프롬프트를 바꾸면 평가에 그대로 반영된다.
- **정답 확장**: `eval/retrieval_eval.py`와 같은 규칙을 쓴다. 공시 정정본, 같은 사건 뉴스(`event_id`), 청크 중복으로 내용이 다른 문서에 남은 경우(`doc_alias`), `also_accept`를 정답으로 인정한다.
- **채점 모델 분리**: 생성(gpt-5.4-mini)보다 큰 모델(gpt-5.4)로 채점한다. 채점자는 정답 기준(`answer_key`)과 챗봇이 받은 [근거]를 함께 본다.
- 4개 스레드로 병렬 실행한다. 79문항 전체가 약 1.5분, 생성 토큰은 입력 36만·출력 2만 개다.

## 2. 지표

| 구분 | 지표 | 산출 |
|---|---|---|
| 검색 | Hit@1 · Hit@3 · Hit@6, MRR | 체인이 생성 모델에 넘긴 문서 6개 안에서 정답 문서의 순위 |
| 인용 | 인용 정답률 | 답변이 `[n]`으로 인용한 문서 중 정답 문서가 있는 문항 비율 |
| | 잘못된 번호 | [근거]에 없는 번호를 인용한 문항 |
| 거절 | 거절 정확도 | 답변 불가 문항이 `[답변 불가]`로 시작하는 비율 |
| | 과잉 거절 | 답변 가능 문항을 거절한 비율 (거절하면 정확도 0) |
| 답변 | 정확도 | LLM 채점: correct 1 · partial 0.5 · wrong 0 |
| | 근거 충실도 | 답변의 사실 주장이 [근거]에 있는가: supported 1 · partial 0.5 · unsupported 0 |
| | 상충 처리 | 비교·종합 문항에서 출처별 차이·기준·시점을 함께 제시했는가 |
| 비용 | 지연 · 토큰 | 문항당 지연 중앙값, 입력·출력 토큰 합계 |

채점자는 정답 기준의 부가 조건(성장률, 비중 등)이 빠져도 partial을 주는 경향이 있어, 정확도는 다소 엄격하게 나온다.

## 4. 관찰

**정확도 × 검색 결과 (답변 가능 68문항)**

| LLM 채점 | 정답 문서가 상위 6개 안 | 밖 | 합계 |
|---|---|---|---|
| correct | 18 | 2 | 20 |
| partial | 24 | 15 | 39 |
| wrong | 2 | 7 | 9 |

- 근거 충실도는 0.93이다. 답변이 근거 밖 사실을 만드는 경우는 드물다.
- **wrong은 주로 검색 실패다(9건 중 7건)**. 원인은 [indexing.md §6](indexing.md)의 검색 실패 원인과 같다: 표 위주 공시, 시점 조건, 같은 회사의 비슷한 공시, 종합 질문의 근거 다양성.
- **partial은 주로 근거를 찾고도 답이 불완전한 경우다(39건 중 24건)**.
  - 정답 기준의 부가 조건을 빠뜨린 경우가 많다: 성장률(F23), 비중(F22), 영업이익률(F18), 선급금(F06) 등.
  - 비교 문항에서 한쪽만 답한 경우도 있다(C03, C04).
  - 일부는 채점 기준이 엄격한 탓이므로, 사람 검토로 보정이 필요하다.

**과잉 거절 5건 (F08, F12, F15, F17, C08)**
- 4건(F08, F12, F15, F17)은 정답 문서가 상위 6개 밖이다. 근거가 없을 때 지어내지 않고 거절했으므로 생성은 의도대로 동작했고, 고칠 곳은 검색이다.
- C08은 정답 문서 2개 중 종근당 공시만 2위로 찾고, 대웅제약 베르시포로신 공시는 찾지 못했다.
  - 그런데도 비교의 한쪽 근거가 없다는 이유로 전체를 거절했다.
  - 프롬프트 규칙 6(일부만 답할 수 있으면 답할 수 있는 부분만 답함)이 지켜지지 않은 사례다.

**시점 문항: 정답 문서를 찾고도 다른 시점 수치를 답함 (T03)**
- 삼성바이오로직스 2026년 전망 공시를 1위로 찾았지만, 함께 들어온 다른 해 공시의 수치(5조7,978억원)를 2026년 전망으로 답했다.
- 같은 회사·같은 종류 공시가 여러 해 들어오면, 근거 머리말의 발행일만으로는 대상 연도를 구분하기 어렵다.
- → 공시 머리말에 대상 사업연도를 넣거나, 질문 연도로 메타데이터 필터를 거는 것이 과제다.

**답변 불가 2건 실패**
- **U08 (ADC 부작용, 의학적 조언)**: 답변 중간에 `[답변 불가]`를 넣고 앞부분에서는 일반 설명을 했다. 프롬프트의 '맨 앞에 표시' 규칙이 지켜지지 않았다. → 범위 밖 질문 거절을 프롬프트 맨 앞 규칙으로 올리거나, 질문 분류를 먼저 하는 단계가 필요하다.
- **U10 (비대면 진료 이용자 만족도)**: 챗봇은 근거를 들어 답했다. 보건복지부 보도자료(2023-03-12)가 인용한 국민건강보험공단 조사(만족 77.8%, 재이용 의향 87.8%)와 솔닥 NPS 기사가 지식베이스에 실제로 있다.
  - → **평가셋 문항 쪽 오류**로 보인다. 정책 원문을 보강하면서 근거가 생겼다. U10을 답변 가능 문항으로 바꾸거나, 질문을 '플랫폼 이용 후기' 같은 수집하지 않은 영역으로 좁혀야 한다.

**측정 잡음**
- 같은 `structure` 설정을 두 번 돌리면(§3의 1차 실행과 이번 실행) 검색 순위는 79문항 모두 같다.
- 생성·채점 결과는 7문항에서 달라졌다. 정확도는 0.581 → 0.588(+0.007), 근거 충실도는 0.929 → 0.968이다.
- 따라서 **Hit@k는 결정적이고, 정확도·충실도는 ±0.01~0.04 정도 흔들린다**. 1~2문항 차이는 설정 차이로 해석하지 않는다.

**structure vs fixed**
- **Hit@3: structure가 7.4%p 높다.** structure만 맞힌 문항은 7개(F03·F05·F25·F27·T05·T06·S09), fixed만 맞힌 문항은 2개(S06·F35)다.
  - 시점(+14%p)·사실(+8%p) 문항에서 차이가 나고, 검색 단독 평가([indexing.md §6](indexing.md))와 같은 방향이다.
- **Hit@6과 정확도는 fixed가 약간 높다.**
  - Hit@6 차이는 +2.9%p다. fixed만 맞힌 문항이 5개(F04·F19·C02·S06·T12), structure만 맞힌 문항이 3개다.
  - 정확도 차이는 +0.022다. 10문항에서 달라졌고 순차이는 1.5문항으로, 위 측정 잡음 범위 안이다.
  - 원인 후보: fixed 청크가 더 길어(중앙값 746자 vs 538자) 같은 6문서라도 생성 모델이 받는 문맥이 17% 많다(입력 토큰 5,370 vs 4,597). 상위 3위 밖의 정답 문서도 문맥에 함께 들어오면 답할 수 있다.
- **결정: structure 유지.**
  - 순위 품질 지표(Hit@1·Hit@3·MRR)가 모두 높다. 정확도 차이는 잡음 범위다.
  - 같은 문맥 예산에서 토큰을 14% 덜 쓴다.
  - 근거를 3~4개로 줄이거나 재정렬을 붙일 때는 상위 순위 품질이 더 중요해진다.
  - fixed의 Hit@6 우위는 "문맥량을 늘리면 회수율이 오른다"는 신호로 보고, 검색 개선 단계에서 `structure`의 `k_docs`·문서당 청크 수 조정으로 확인한다.

**structure vs structure_notitle — 청크 머리말(제목·발행처·날짜·섹션)의 효과**
- Hit@3가 −20.6%p로 가장 크게 떨어진다. structure만 맞힌 문항이 17개, notitle만 맞힌 문항은 3개다.
- 정확도는 −0.110, 과잉 거절은 0.074 → 0.191로 오른다. 정답 문서를 못 찾으니 거절이 늘어난다.
- 단, notitle은 생성 모델이 받는 근거에도 제목이 없다. 그래서 정확도 하락에는 검색과 생성 두 효과가 섞여 있다. Hit@k는 검색만의 효과다.
- 종합 문항 Hit@3만 notitle이 높다(0.333 vs 0.111). 정답 문서가 여러 개인 종합 문항은 3문항 차이라 판단하지 않는다.

> **이후 검색기 변경 (2026-11-05, Streamlit 앱 작업 중)** — 위 측정은 이 변경 전 값이다.
> - 문서가 `k_docs`개보다 적게 모이면 청크 pool을 5배로 넓혀 한 번 더 조회한다. 긴 정책 붙임(의약품 목록)의 청크가 pool 40개를 채워 근거가 2문서만 나오던 문제다. 79문항 중 F31 한 문항에만 해당한다.
> - 대화 맥락이 있으면 후속 질문을 검색용 독립 질문으로 다시 쓴다(`chain.condense`). 하네스는 이전 대화 없이 실행하므로 영향이 없다.

## 6. 검색 개선 전후 비교 (2026-11-05)

### 6.1 무엇을 바꿨나 — 실패 분석에서 출발

기준선(dense)에서 Hit@3에 실패한 29문항을 다시 봤다. 실패 원인은 [indexing.md §6](indexing.md)의 분류와 같고, 그중 둘을 고쳤다.

| 실패 원인 | 해당 문항 예 | 개선 | 구현 |
|---|---|---|---|
| 고유명사·제품 코드를 벡터 검색이 구분하지 못함 | F04 LCB14, F08·F09 ALT-B4, F06·C02 SOTIO, F15 코어라인소프트 | **하이브리드 검색**: 벡터 + BM25 키워드 검색을 RRF로 결합 | `indexer/bm25.py`가 인덱스를 만들고(`store/bm25/structure.npz`), `rag/bm25.py`가 읽는다 |
| 질문의 시점 조건 무시 | F12 2024년 10월, F13 2025년 1월, T01·T02·T10 연도별 경과 | **시점 반영**: 질문에 2021~2026년이 있으면 그 연도로 거른 벡터 검색을 RRF에 하나 더 넣음 | `retriever.query_years`, `mode="hybrid_time"` |

- **BM25 토큰**: 한글은 글자 2-gram을 쓴다. 형태소 분석기가 없어도 조사·띄어쓰기 차이를 흡수한다. 영문·숫자는 단어로 쓰고, 하이픈 코드는 붙인 형태도 추가한다(`ALT-B4` → `alt`, `b4`, `altb4`).
  - 색인 대상은 청크 `text`(머리말 포함)다. 57,433청크, 어휘 12.7만 개, 48MB, 생성 34초.
  - 검증: 청크 수가 일치하고, 표본 50개를 자기 텍스트로 검색하면 50/50이 상위 10위 안에 온다.
- **RRF**: 목록별 순위로 `1/(60+순위)`를 더한다. 벡터 유사도와 BM25 점수는 척도가 달라 직접 더하지 않는다.
- **시점은 '필터'가 아니라 '추가 목록'이다.** 질문 연도 밖의 근거도 남는다.
  - 예: "2024년 매출 전망은 연중 어떻게 바뀌었나"의 2023년 말 기사.
  - "2028년" 같은 지식베이스 밖 연도는 무시하므로 답변 불가 판단에 영향이 없다.
- 사이드바 필터(출처·연도·주제)는 BM25 후보에도 똑같이 적용한다(`match_where`).
- 계층 분리를 유지했다. 인덱스는 인덱서가 쓰고 챗봇은 읽기만 한다. `indexer`·`collector` import를 막은 상태에서도 앱이 구동되는 것을 확인했다.

## 7. 재정렬 (hybrid_rerank, 2026-11-05)

### 7.1 무엇을 바꿨나

§6.4의 "정답이 4~6위" 문항(F04·F05·F12 등)을 겨냥했다. 정답 문서를 찾긴 했지만 순서가 밀린 경우다.

- 1차 후보는 `hybrid_time`과 같다. 다만 더 넓게 모은다: 청크 80개(목록마다) → 문서 15개(문서당 2청크, 약 30청크).
- LLM(gpt-5.4-mini) 한 번 호출로 청크마다 질문과의 관련도를 0~10점으로 매긴다.
  - 기준: 질문의 회사·제품·제도·시점이 일치하고 답을 직접 담고 있는가. 다른 사업연도·정정 전후를 구분하게 했다.
  - 청크당 앞 700자만 보여준다. 호출당 입력 약 1.1만 토큰, 약 1.8초.
- 문서 점수는 그 문서 청크 점수의 최댓값이다. 동점이면 원래(RRF) 순위를 따른다. 상위 6개 문서를 답변 근거로 넘긴다.
- GPU가 없어 로컬 cross-encoder 대신 API를 쓴다. `reasoning_effort`를 바꿔 봤지만 기본값이 가장 빠르고 점수도 비슷해서 기본값을 쓴다.
- 호출이 실패하면 원래 순서를 그대로 쓴다(챗봇이 멈추지 않게).
- 구현: `rag/rerank.py`, `retriever.search(mode="hybrid_rerank")`. 인덱스는 바꾸지 않았다.

### 7.2 하네스 수정 — 채점 입력을 '체인이 실제로 받은 근거'로

첫 측정에서 근거 충실도가 0.953 → 0.84 · 0.80으로 크게 떨어졌다. 원인은 하네스 쪽이었다.
- 채점기에 넘길 근거를 `retriever.search(q)`로 **다시 검색**해 만들고 있었다. 검색이 결정적이라는 가정이었다.
- 재정렬은 LLM이라 다시 검색하면 근거 문서가 달라진다. 그래서 채점기가 챗봇이 보지 않은 근거로 채점했다.
  - 채점 이유에 "근거에 없는 2025·2026 기사", "인용 번호가 실제 근거와 어긋남"이 나왔다.
- 수정: `chain.ask()`가 LLM에 넘긴 근거 블록(`context`)을 함께 반환하고, 하네스는 그것으로 채점한다.
  - 수정 후 C05의 근거 충실도는 0.0 → 1.0이 됐다.
- dense·hybrid·hybrid_time은 검색이 결정적이라 §3~§6 결과는 이 문제의 영향을 받지 않는다.

- 검색은 같으므로 Hit@k·MRR은 같다. correct·partial·wrong 수도 21·40·7로 같다.
- 요건 준수(규칙 기반 집계):
  - 거절 답변 12건 모두 요구 문구로 정확히 시작한다.
  - 거절하지 않은 답변 67건 중 61건이 "공시[1]"처럼 출처 종류와 근거 번호를 함께 적는다. 이전에는 이 형태가 0건이었다.
  - 규칙 번호를 노출한 답변은 0건이다(T11·T13의 '규칙'은 「의료법 시행규칙」 같은 법령명).
- 문항 단위 변화: 정확도가 오른 문항 5개(F05·F10·F25·F35·T02), 내린 문항 5개(F06·F27·C08·T06·T12)다. S01은 과잉 거절이 풀렸다.

### 8.3 해석

- **정확도와 거절은 손실 없이 필수 요건을 맞췄다.** 오르내린 문항 수가 같고(5·5) 총합도 같아, 정확도 변화는 실행 간 잡음(§6.3, 최대 0.05) 안이다.
- **근거 충실도 -0.03은 비교 질문 3개(C03·C07·C09, 각 1.0 → 0.5)에서 나왔다.** 채점 이유가 문항마다 다르다(정답 기준과 다른 축, 다른 시점 기사로 확장 등). 그래서 프롬프트 탓으로 단정하기 어렵고 잡음 범위로 본다. 다음 반복 측정(§9-4)에서 다시 확인한다.
- **결정: 새 프롬프트를 기본으로 쓴다.** 과제 필수 요건을 만족하고, 정확도·거절 지표는 그대로이며, 과잉 거절은 줄었다.
